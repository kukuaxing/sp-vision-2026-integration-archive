> 22字节下行/12字节上行协议，仅用于保留测试证据。当前下位机使用
> 14字节下行/20字节上行，IMU由下位机发送给小电脑。实际接板必须参考

日期：2026-09-01

分支：`test/xuc-virtual-link`

基础分支：`integration/xuc-firmware-safety`

## 测试目的

在主控板尚未返回的情况下，使用 Linux PTY 虚拟串口模拟
TWLInfantry 下位机，验证上位机真实 `io::XucSender` 的双向通信链路。

测试不连接主控板、电机或发射机构。

## 测试内容

- 上位机发送 22 字节 `XucRxPacket`。
- 虚拟下位机返回 12 字节 `XucTxPacket`。
- 串口配置为 460800、8N1、无流控。
- 协议角度单位为弧度。
- 校验包头、控制位、开火位、yaw、pitch 和 IMU 姿态。
- 校验上下位机 CRC16。
- 注入错误 CRC 反馈。
- 注入串口噪声。
- 将反馈包拆分为多次写入。
- 模拟反馈中断。
- 验证 500 ms 上位机反馈超时。
- 模拟通信恢复。

## 测试结果

- 上位机命令包：80
- 上位机命令包 CRC 错误：0
- 命令字段错误：0
- 注入错误 CRC 反馈：14
- 正常反馈：48
- 静默期间命令包：18
- 通信恢复反馈：32
- C++ 测试退出码：0
- Python 虚拟下位机退出码：0

最终结果：

- `XUC_LINK_RESULT=PASS`
- `VIRTUAL_LOWER_RESULT=PASS`
- `TEST_EXIT=0`

## 已验证结论

1. 上位机真实 `XucSender` 能发送符合下位机协议的 22 字节命令包。
2. yaw、pitch 和 IMU 字段的符号与单位符合当前配置。
3. 上位机能够解析合法的 12 字节下位机反馈包。
4. 错误 CRC 反馈不会被接受。
5. 接收缓冲能够处理噪声和拆分数据包。
6. 下位机反馈停止 500 ms 后，`rx_valid()` 自动失效。
7. 下位机反馈恢复后，链路可自动恢复。
