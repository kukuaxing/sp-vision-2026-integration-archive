## 1. 验证目的

```text
海康相机
  → 装甲板检测
```

本次测试不包含真实云台控制和发弹。

## 2. 测试环境

- 相机：海康 USB 相机
- IMU：串口设备，115200 波特率
- IMU协议：`5A A5`，82字节数据帧
- IMU姿态传输：串口 → `imu_to_can` → 虚拟CAN `can0`
- CAN姿态帧ID：`0x150`
- XUC下位机：未连接
- 发弹：禁用
- 云台运动：人工缓慢转动

## 3. IMU桥问题及修复

原 `imu_to_can.cpp` 将数据帧运行状态字节限制为：

```text
0x1A 或 0x1B
```

实际设备数据中的状态字节为：

```text
0x1E
```

导致程序能够打开串口，但一直不向CAN发送姿态帧。

修复方式：不再固定限制运行状态字节，只校验稳定的协议字段、四元数有效性、时间戳连续性和相邻四元数连续性。

实测原始数据：

- 约2秒读取16382字节
- 检测到199帧候选帧
- 199帧四元数模长均合理
- 时间戳增量绝大多数为10
- 修复后CAN能够持续输出姿态帧
- CBoard能够正确解析姿态

## 4. 相机时间同步

海康相机当前不能提供项目原先依赖的有效 `frame_id`。

处理方式：在相机时间戳和IMU数据使用同一 `steady_clock` 时间基准的前提下，通过：

```cpp
cboard.imu_at(t)
```

取得图像时间对应的IMU姿态，并用于：

```cpp
solver.set_R_gimbal2world(q)
```

修复后日志中的桥输出、CBoard解包姿态和时间戳插值姿态一致。

## 5. IMU安装矩阵验证

原安装矩阵：

```yaml
R_gimbal2imubody: [-1, 0, 0, 0, -1, 0, 0, 0, 1]
```

在固定装甲板、人工转动云台时，世界坐标发生明显漂移。一次动态测试中最大漂移约为0.59米，说明云台运动未在坐标变换中正确抵消。

通过对合法旋转矩阵候选进行离线比较，并进行 yaw/pitch 联合实测，最终采用：

```yaml
R_gimbal2imubody: [-1, 0, 0, 0, 1, 0, 0, 0, -1]
```

该矩阵等价于绕Y轴旋转180°。

已同步写入：

```text
configs/standard_hikrobot.yaml
configs/calibration_hikrobot.yaml
```

## 6. 固定目标静态测试

距离约1.12米时：

- PnP距离均值：1.1222米
- PnP距离标准差：0.0075米
- Tracker距离均值：1.1225米
- Tracker距离标准差：0.0028米
- 有效记录：49条
- 命令yaw跨度：0.89°
- 命令pitch跨度：0.16°

Tracker能够明显降低测量抖动。

## 7. 第二候选矩阵动态测试

测试顺序：

1. 保持静止
2. 缓慢转动yaw
3. 保持
4. 缓慢返回
5. 缓慢转动pitch
6. 保持
7. 返回原位

测试结果：

- 有效DRYRUN记录：74条
- 无目标记录：0条
- 世界坐标最大漂移：0.0341米
- 世界坐标RMS漂移：0.0181米
- 世界yaw跨度：1.00°
- 世界pitch跨度：0.63°
- 命令yaw跨度：1.00°
- 命令pitch跨度：0.65°
- 人工转动的云台yaw跨度约2.91°
- 人工转动的云台pitch跨度约3.58°

与原矩阵下约0.59米的动态漂移相比，新的安装矩阵显著改善了固定目标的世界坐标稳定性。

## 8. 关于当前约180°的姿态

当前云台因拆车检修而处于与正常车头方向相反的安装状态，因此日志中的绝对yaw和部分控制命令接近±180°。

这不是本次坐标融合失败的证据。本次验证关注的是：

```text
云台转动时，固定目标的世界坐标是否保持稳定
```

目前不应通过修改相机外参或增加固定角度偏置来强行将绝对yaw归零。
