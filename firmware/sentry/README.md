## IMU姿态接口（2026-10-16当前源码）

CH010/HI226的控制反馈和V2上行roll/pitch/yaw，由完整HI91载荷中的WXYZ机体到导航系四元数归一化后提取为常规ZYX角，满足 `R = Rz(yaw) Ry(pitch) Rx(roll)`。厂家原生roll/pitch标签默认属于ENU/312约定，保留在 `GetDeviceEuler()` 仅供诊断，不直接进入控制或上行角字段。

- 只接受完整、单独的76字节HI91载荷（含帧头共82字节）；不兼容截短姿态包或混合子包载荷。
- 四元数必须有限，模长平方在 `[0.98, 1.02]` 内；异常值不提交姿态、时间、epoch、有效样本数或新鲜到达时刻。重复设备时间不刷新样本。
- 角速度仍是厂家XYZ本体系角速度，符号和顺序不变；接收单位deg/s，上行rad/s。旧IMU601分支不受此次语义修正影响。
- 安装旋转、手眼外参、电机正负方向和闭环稳定性须单独核验，认证位不因此置位。原镜像`1eebc404`的AUTO复测仍有大幅摆动；当前`574df53b`保留下方有界AUTO参考并补齐实际CAN反馈看门狗和动作撤销，已完成全1MiB读回和STOP静态检查，自动闭环仍待现场验收，见[验证记录](../../logs/sentinel-v2-validation.json)。

探针日志的 `raw_rpy_deg` 指收到的MCU字段：四元数修正前的旧记录为厂家原生角，采用修正源码的固件输出后为MCU的ZYX角。分析时须绑定固件版本，不能把新日志继续当作原生312。字段、来源和历史验收见[通信文档](../../docs/sentinel_protocol.md)。

## 构建

在仓库根目录，用GNU Arm工具链及Ninja执行：

```sh
cmake -S firmware/sentry -B firmware/sentry/build -G Ninja -DCMAKE_TOOLCHAIN_FILE=cmake/arm-none-eabi-toolchain.cmake -DCMAKE_BUILD_TYPE=Debug
cmake --build firmware/sentry/build
```

输出为build/STM32F405.elf及STM32F405.bin。编译产物不提交Git。2026-10-15历史版本经用户授权完成烧录、全Flash读回校验及复位；该记录不能作为后续姿态修正镜像的部署凭据。运行开关与对应烧录结果见SOURCE.md及通信文档。

## STOP保持与只跟随复测

STOP或失去AIM时，每轴独立捕获一次有效位置，缺反馈的轴等待首次有效反馈；连续保持不再追随之后的实际位置漂移。手动或AIM恢复后，下次保持重新捕获。RESET仍沿用原有复位语义。

## AUTO位置参考修正（已部署，自动闭环待验收）

AUTO不再每5ms把IMU误差累加到旧电机位置目标。两轴均有有限、范围内的有效反馈后，首次接管只给当前位置；后续每周期重新计算“当前电机位置 + 0.25倍IMU误差”，小Yaw参考最多领先当前位置1°，Pitch最多0.5°。重复误差、冻结编码器及跨包更新都不会积累旧目标。缺反馈、DM故障、非有限数据或当前姿态在软限位外时保持现有位置并禁止自动拨弹；手动、STOP或失去AIM后，下次接管重新从当前位置开始。原机械限位、协议有效期及保持行为保留。

这些是电机位置参考的约束，不能证明实物速度或闭环稳定。2026-10-17已加入仅由真实CAN回调刷新的100ms看门狗，缓存重复解码不续期；反馈过期清输出和位置积分，拨弹撤销会同时清除积压位置目标。摩擦轮要求两轮各自新鲜、方向正确并达到原转速比例，不能用两轮平均值代替。Motor的三环PID数组修为三个槽位，消除原第三环越界；原控制增益不变。真实闭环由用户启动复测。

DM电机只在STOP/RESET下发送启动使能，收到之后的新鲜status=1才可运动。运行后反馈超时、失能或驱动故障会锁存停机，周期使能和恢复反馈都不能恢复旧动作。**遇到这种故障，应保持STOP/RESET并重启主控。** SWD字段为`DMmotor[i].safety_fault_latched`和`safety_fault_reason`（0正常、1反馈超时、2运行后失能、3驱动故障）。V2链路许可位不表示该电机已实际使能。

用户可在小电脑执行 `tools/field_start_autoaim.sh --follow-only`，先保持STOP检查识别。该可选入口仅覆盖现有运行缓存，关闭发射和摩擦轮；默认启动及正式配置不改。`--check --follow-only`只预检，不启动设备或生成缓存。
