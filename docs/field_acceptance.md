# 回到实车后的接续验收

本文件是待执行清单，不是已完成记录。离线结果见 `offline_development.md`；实车状态仍以 2026-09-17 的 `status.md` 为准。当前 P 轴保护、旧外参不可用等状态必须在现场重新确认。

## 先让电控交付可稳定使用的接口

交付 `rmv_protocol.md` 与 `python -m tools.rmv vectors` 生成的黄金报文；Python Board 是协议参考夹具，不能将其机械参数复制进固件。

电控应同时提供以下可读回信息：

| 项目 | 交付内容 | 视觉侧对应检查 |
|---|---|---|
| 版本 | firmware/boot/session、能力位、参数和安装版本 | 重启使旧会话/姿态/许可失效，能力与实现相符 |
| 姿态 | sensor_id=0 的完整相机支架 G→W 四元数、源计数、采样时间、epoch、有效标志 | 单独转小 Y、P、大 Y；方向/幅值正确且时间不重复 |
| 关节 | 实际位置/速度、目标、反馈年龄、可用/使能/回零/故障状态 | 与实际轴一一对应，禁止用指令值冒充测量 |
| 控制 | 世界视线或标定关节目标、接收序号与已采用序号、许可/所有权、目标到期 | 丢帧/遥控接管后进入约定本地策略，心跳不续期旧目标 |
| 参数 | 枚举、类型/单位/范围/权限、事务提交、持久化状态 | 修改→读回→重启读回；失败不能出现一半生效 |
| 诊断 | 实际更新率、CRC/丢弃计数、排队/控制抖动、错误原因 | 用真实统计定位问题，不填“永远正常”的占位值 |

本轮用户确认：小 Y IMU 在 UART3，大 Y IMU 在 UART5。UART 名称不足以证明安装关系。若小 Y IMU 不随 P 运动，须由同步编码器和安装关系合成完整 G 姿态，或双方重新明确由视觉合成的接口；不能直接代用。

可选的发射、底盘、前馈、回零、大 Y 协调只有实现且验收后才能置相应能力位。协议有扩展格式，不代表当前客户端或固件全部支持。通信固定选择一种协议，不在同一字节流混猜 SP、HI91 和 RMV。

## 视觉侧按顺序接入

1. **只读核对。** 在小电脑编译对应环境，记录固件/软件/配置/模型哈希。先确认 USB 路径、波特率、握手、时钟不确定度、状态和两路姿态，不启动自动跟随。
2. **恢复标定条件。** 按电控确认的流程处理 P 轴当前保护状态，核对零位/机械范围；验证两轴姿态后才将 `calibration_pose_verified` 放行。使用已完成的新内参采集新外参。
3. **核对坐标。** RMV 是 pitch 向上为正；当前 Aimer 输出沿用 pitch 向上为负。正式接入必须在明确边界转换，不能复用 SP 的经验符号/倍率。`Solver::set_R_gimbal2world_direct` 接受已经转换好的 G→W，不再次套旧 IMU 安装旋转。
4. **完成被动记录适配。** 新记录 Writer 已定义数据格式，但 `standard` 尚未挂入全部事件。接入相机实际时间、姿态源、Tracker 状态、下发意图和 MCU 已采用反馈，并标出相机曝光时间是实测还是估计。队列溢出、断流必须留下 health 记录。
5. **先小幅跟踪。** 由用户启动现场程序，依次检查静态目标、单轴小幅阶跃/往返、双轴运动、短丢帧、遥控接管与串口中断。姿态、图像时钟未对齐或许可失效时，不继续产生目标。
6. **再优化预测和发射。** 用同一批记录比较现有算法与候选值；测量弹速、出膛时刻、轴跟踪误差。先核对实际命令采用时间，再判断是预测、控制还是弹道偏差。大 Y、底盘和发射分别验收。

## 每次现场带回什么

记录原始图像、实际采样时刻及其时间域、检测角点/置信度/颜色、目标估计、完整姿态、控制意图、实际关节和已采用序号。保存参数/外参/模型/软件版本快照，注明场景距离、运动方式及是否发射。没有来源的旧录像只能做检测回放，不作为本车时间同步或跟踪闭环证据。

至少带回静止、水平移动、垂直移动、旋转、短遮挡、轴换向六类片段，保留失败片段。记录真实结果后再确定阈值；不要用这次合成基准的排名代替选型。

硬件尚未实现 RMV 时，继续维护现有 SP 入口。新协议启用、外参更新与现场闭环应分阶段完成，使每一步都有独立可复现证据。
