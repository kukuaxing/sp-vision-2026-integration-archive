# 离线估计器对照基准

本基准直接编译工程里的 `YawESKF`、`ArmorMotionFilter`、`RobustRangeFilter`，向它们输入有真值的合成观测，再与固定参数的简单基线对照。它验证估计器的数学行为，不能代表实车识别精度、命中率或小电脑帧率。

```powershell
python scripts/benchmark_offline.py
python -m unittest discover -s tests/benchmark -v
```

Windows 使用本机 MSVC，Linux 可使用普通 C++17 编译器；脚本不启动 WSL、不连接设备或网络，只串行启动一个编译进程。依赖仅为仓库内 Eigen 和 Python 标准库。构建文件进入 `build/offline/`，原始逐帧结果、汇总和报告分别写入 `logs/benchmark/samples.csv`、`summary.json`、`report.md`。

## 场景与公平性

- 100 Hz，每场景 8 秒，固定种子 `17 / 2026 / 98173`，全部方法统一排除最初 1 秒的暖机数据。显式 LCG 与 12 个均匀数求和产生可重复的近似高斯噪声。
- yaw：匀速、1→4 rad/s 的转速斜坡、±π 跨界、0.8 秒连续丢帧加间歇丢帧、稀疏异常观测、60 ms 延迟但被误当成当前观测。
- armor：缓慢曲线平移、加速、丢帧、三维异常点、把新目标位置突然交给旧滤波器的重捕获压力场景。
- range：匀速、加速、丢帧、仅原始距离存在异常点、仅模型距离带有 0.35 m 偏置。
- yaw/armor 基线为固定 `alpha=0.35, beta=0.04` 的恒速观察器；yaw 基线与 ESKF 得到相同的 90° 等价面信息。range 基线为原始距离或模型距离的 80 ms EMA。未为任一方法调参，也不要求现有实现必须获胜。
- yaw 和 range 读取唯一正式 `configs/standard.yaml` 中相关标量，自动生成构建目录里的头文件。其余字段、armor 配置采用实际类默认值；它们与当前调用方一致。重复或不支持的配置格式会报错，不静默退回另一份配置。

当前共 16 个场景、37 个“场景/方法”组合、88,800 行逐帧输出。同一编译器生成的可执行文件连续运行两次，CSV 必须逐字节相同；该要求不宣称不同编译器的浮点结果逐字节相同。

## 如何读结果

统计包括全部有限输出的 RMSE、绝对误差 P95/最大值、有效输出上的同类指标、有效输出数量、接收观测数量，以及不同时间段的误差。**全部输出的误差也会保留**，不会通过只挑 `trusted` 的时刻掩盖坏状态。

yaw 使用 rad/rad·s⁻¹；armor 使用三维位置误差范数 m、速度误差范数 m/s；range 使用 m。yaw/armor 的 `valid` 指生产滤波器的 `trusted()`，基线没有此门禁，所以有效数量不能直接作为安全性的排名。range 没有 fresh observation 的时刻不输出距离，分母仍包含全部调度时刻。

yaw 同时报告模 2π 和模 π/2 的误差。四块完全相同的面在丢失观测后可能无法恢复唯一面号，因此持久 90° 偏移与相位误差必须区分；实际长短半径、不同高度或不可靠面关联还需要完整 Target 回放才能评价。

yaw/armor 另报告 0.40 秒预测误差。响应时间采用明示的误差容差与连续 20 个有效采样窗口，`null` 表示该记录内未稳定到阈值；这些阈值只是描述响应的尺子，不是人为设定的算法验收门槛。

`summary.json` 记录使用的配置、编译命令、种子、源文件 SHA-256 和 CSV SHA-256，可判断报告是否对应当前源码。正式配置或算法改变后应重新生成报告。

## 本次实际发现

修复前 `YawESKF::predict(0.40)` 只积分 `max_dt_s=0.10` 秒。`Target::ekf_x()` 又会用可信 yaw 状态覆盖车辆 EKF，从而把短时预测当作完整弹道预测。新增回归先复现失败：同一收敛状态相对其自身恒加速度模型少转 **1.39191 rad**。修复后完整积分 0.40 秒，误差约 `3.55e-15 rad`，与 40 次 0.01 秒的角度、速率和协方差一致。异常 duration 不会造成无限循环，数值溢出后需重新获取观测并建立信任。原始前后输出保存在 `logs/benchmark/yaw_horizon_before.txt` 和 `yaw_horizon_after.txt`，不提交日志。

修复后、当前参数下的三种代表性取舍如下。所有数值只适用于本文件定义的合成输入：

| 场景 | 当前实现 | 简单基线 | 含义 |
|---|---:|---:|---|
| yaw 匀速，当前角度 RMSE | 0.01394 rad | 0.01707 rad | 当前角度滤波更平滑 |
| yaw 匀速，0.40 s 预测 RMSE | 0.13150 rad | 0.08883 rad | 加速度估计中的噪声会放大长期预测误差 |
| yaw 丢帧，模 90° 相位 RMSE | 0.10407 rad | 0.06675 rad | 丢失观测期间的恒加速度外推也有代价 |
| armor 异常点，位置 RMSE | 0.00947 m | 0.15505 m | NIS 拒绝明显降低异常点污染 |
| range 模型偏置，距离 RMSE | 0.24053 m | 原始距离 EMA 0.02943 m | 强信任模型不能修正模型本身的系统偏差 |

这些结果没有触发正式参数调整。合成真值没有包含相机畸变残差、PnP 偏差与相关噪声、真实装甲面选择、串口时间同步、图像与 IMU 对齐、电机跟踪或弹道误差。可继续用固定回放比较候选模型；最终选择需要实际录像与同步状态记录。

## Planner 时间一致性回归

审查真实 `Target → Planner → TinyMPC` 路径又发现两个独立问题：

1. Planner 原先先 `target.predict(-0.51)`，再连续正向预测生成以当前时刻为中心的窗口。车辆 EKF 接受负时间，但 yaw/armor 子滤波器忽略负时间，所以其窗口相位没有同步回退。现在由 `Target::ekf_x_at(dt)` / `armor_xyza_list_at(dt)` 对当前运动学均值做只读采样；支持负相对时间，不改滤波器状态、协方差或信任判定，窗口中央严格对应 `dt=0`。
2. optional-target 入口先计入执行延迟，内部 Target 入口又计入一次。现在外层只补观测年龄和处理延迟，内层统一补弹丸飞行与执行延迟。新增显式 `now` 的调用方式便于确定性回放；原有两参数调用仍使用真实单调时钟。

`tests/offline/planner_time_test.cpp` 把 fixture 的 yaw 速率协方差信任上限提高到 100，并断言整段窗口仍使用可信 yaw。这是为了隔离时间一致性：默认上限可能在窗口中途退回车辆 EKF，恰好掩盖中央采样错位，并不代表应修改正式参数。修复前实际复现中央 yaw 误差 **-0.0342751 rad**，日志在 `logs/benchmark/planner_before.txt`。这个数值属于特定测试夹具，不能声称实车固定偏差约 2°。

同一测试同时检查可信/未可信 yaw、负/零/正相对时间、输入数值边界、只读采样不改变子滤波器状态，以及固定时钟下 40 ms 执行延迟只计算一次。它由原生 CMake 离线测试目标编译真实 Planner 与 TinyMPC 数学源码。
