## 3. 仿真链路与防止“用答案验证答案”

1. `fixed_target_world.hpp` 独立生成四块板的运动与空间端点，按现有相机内参、畸变和外参投影为二维角点。相机初始姿态朝向射击点，之后跟随实际虚拟云台角度；解算器读取对应姿态，可另外注入姿态偏差。角点列表不携带物理面编号。
2. 正式 Solver 自行做姿态解算，Tracker 自行初始化、关联面身份和估计转速。固定中心拟合只能读取已经关联并接受的观测；真实中心和真实转速仅用于实验环境及事后误差统计。
3. 正式 Aimer 读取正式 YAML 的预测延迟和已标定弹速。使用它已有的确定性时间路径，并补齐本实验设置的帧龄，避免离线运行速度影响预测时刻。预测副本做时移，原始跟踪器状态不被篡改。
4. 复用预测残差质量检查、两帧窗口与每面每次过面去重。yaw命令指向估计中心，pitch采用预测弹道；云台可设置一阶时间常数、限速及限加速度，1ms子步积分。仿真俯仰资格使用虚拟编码器跟随误差调用正式HighSpeedPitchGate，不等同于完整主入口的图像/弹道俯仰残差。正式Aimer的6°硬件pitch偏置在校准虚拟坐标转换时抵消；既有机械零位和impact微调不直接当成虚拟枪口误差，未修改上车调参。
5. 下发接受后消耗一次预算、提交过面编号并排入出膛事件队列。到了真实虚拟出膛时刻，才读取**此时的实际云台角度**并叠加独立弹速/角度散布生成弹丸；避免把下发时刻的理想角度冻结成未来枪口方向。抖动可能改变出膛顺序，碰撞及记分按实际到达时刻排序。
6. 碰撞器按四块真实运动矩形分别寻找“从正面穿过平面”的时刻，再用二分求交和有限宽高判断。没有用预测器选择的面或预计命中时刻作为碰撞答案。默认积分区间0.5ms，专项测试对照2ms/0.25ms。
7. 物理碰撞发生时才扣HP，清零后不额外计伤害。**HP不反馈给发射控制，所有正常轮次统一跑满50发预算**，另外记录第30次命中时刻与全组命中率。若因资格不足在60s观察窗口内没发满，剩余预算仍保留在分母中，不能靠少发提高成绩。每条下发对应一发是本模型假设，真实漏发尚未模拟。

压力测试可设置整帧漏检、角点高斯噪声/共同偏差、帧龄抖动、相机时间戳偏差、姿态偏差、真实出膛均值与随机抖动、弹速波动、枪口固定偏差和双轴角散布。像素、帧龄、漏检、发弹时序与弹丸散布使用分开的随机流，控制变量对照保持相同种子。

未覆盖：真实YOLO漏检分布、曝光运动模糊/滚动快门、完整IMU同步与误差相关性、真实电机PID、串口许可与MCU排队/漏发、气阻、靶车壳体遮挡及裁判传感器模型、导航往返和比赛开始信号。默认法向速度门槛0，只表示几何命中；这些项目尚未通过实车验证。

### 3.1 仿真发现并修复的正式调用缺陷

`FacePredictionResidual` 已有短资格间断保留历史的设计，但正式调用方在固定模型当帧不可用时把中心距离设成NaN，令它的“仍为同一上下文”判断失败。约5%随机漏检就可能反复清空历史，长期积累不出开火质量资格。

在 `HighSpeedVision::update_residual` 增加最多150ms的同目标距离/角速度元数据保留，并在 `src/standard.cpp` 与仿真调用相同适配方法。缺观测的当帧不更改 `context_valid/observations_valid/forecast_valid`，不能授权发射；不更新保留时间；超时、目标epoch改变、模型重建、导航/姿态上下文无效或旋向不一致时清除。没有放宽射击窗口和误差门槛。

新增回归覆盖双旋向、周期性漏检后重新积累成功、缺帧关闭发射、连续缺帧到期、换目标、重建、旋向变化及上下文失效。正式standard已重新编译并核对源码身份，没有运行硬件程序。

较强组合假设：15%漏检、1.5px角点噪声、8ms帧龄标准差、时间戳+10ms、姿态yaw+0.3°；云台τ120ms、真实出膛350ms且标准差40ms、弹速标准差0.7m/s、枪口yaw/pitch固定误差+0.15°/+0.12°、角散布标准差0.30°/0.55°。有限云台统一限速120°/s、限加速度720°/s²。**这些都是可检验假设，不是本机实测误差。**

实际延迟从250至410ms按20ms离散扫描，预测保持330ms：250/410ms为0%，270ms为17.5%，290/310/330/350/370ms为100%，390ms为21%。扫描使用无其他误差环境，不能把±40ms当作实机可用延迟公差，也未精确定位临界点。

值得优先验证的是时序：4.56rad/s下，80ms对应约20.9°相位误差；0.26m半径时横向偏差量级约9.3cm，已超过本模型板宽的一半6.75cm。两组延迟对照都擦过，证明这套门控对“预测时间与真实出膛时间是否一致”敏感。它没有测出实车真实延迟，更没有证实实车问题一定是80ms误差；不能把330ms当成已完成标定。

## 5. 文件与运行方法

- `simulation/fixed_target.json`：当前固定旋转靶场景、参数来源与假设。是离线世界参数，不是第二份上车YAML。
- `simulation/src/fixed_target_sim.cpp`：复用正式算法的离线入口。
- `simulation/src/fixed_target_world.hpp`：独立运动/弹道/碰撞/计分模型。
- `simulation/src/fixed_target_plant.hpp`：有限云台响应与实际枪口状态。
- `simulation/src/fixed_target_world_test.cpp`：可解析验证的碰撞与配额测试。
- `simulation/run_fixed_target.py`、`simulation/fixed_target_report.html`：执行与生成无外部资源依赖的可播放HTML回放。
- `simulation/validate_fixed_target.py`：独立核对300血/50发记分、事件因果时序、确定性和正式二进制源码身份。
- `logs/fixed-target-simulation.json`、`.html`：本轮400轮结果与回放，包含运行配置/二进制/关键源码SHA-256。

小电脑运行：

```bash
cd /home/rcsdart/rm27
cmake -S . -B build/native-offline \
  -DSP_BUILD_OFFLINE_ONLY=ON -DSP_OFFLINE_WITH_VISION=ON \
  -DCMAKE_BUILD_TYPE=Release
cmake --build build/native-offline -j2 --target fixed_target_sim fixed_target_world_test
ctest --test-dir build/native-offline -R fixed_target_world_test --output-on-failure
python3 simulation/run_fixed_target.py --suite --stress --delay-sweep
python3 simulation/validate_fixed_target.py --repeat
```

所需OpenCV/Eigen/yaml-cpp/fmt/spdlog/nlohmann_json以及Python PyYAML均已在当前小电脑构建环境使用成功；无需Godot、ROS图形节点、相机或下位机。

自定义单组实验时，只修改物理端延迟，例如：

```bash
python3 simulation/run_fixed_target.py --muzzle-delay-ms 290 --noise-px 1 --fps 50
```

该命令仍使用正式YAML中的330ms预测延迟，不会将真实值泄露给预测器。CLI覆盖只存在系统临时目录，运行结束清理；不改正式配置。默认覆盖当前 `logs/fixed-target-simulation.json/.html`，要保留本轮对照可指定其他清晰的日志输出路径，不复制工程或正式配置。

`--seeds 27,83,149` 可显式指定种子。浏览器打开输出HTML，可切换20组实验/旋向/相位、播放/暂停/倍速和拖动时间轴，查看运动、角点、下发数和HP。多种子汇总包含全部轮次，仅首个种子的8轮保留逐帧回放以控制文件体积。无需网络连接。

### 7.1 渲染与输入边界

- 共用 `fixed_target_camera.hpp` 的当前相机内参、畸变和外参，输出1440×1080图像。单独检查它与正式Solver的几何投影一致，并拒绝相机背后的目标。
- `fixed_target_renderer.hpp` 按四块板的空间姿态进行透视纹理映射、正面可见性判断和远近遮挡排序。只在目标局部区域做曝光积分与图像退化，背景为固定灰色，不能验证复杂赛场背景中的误检。
- 4号纹理为程序绘制，512×384像素，灯条中心端点固定在(64,112)/(448,112)/(448,272)/(64,272)。映射到135mm灯条间距及56mm长度，纹理平面约180×134mm，数字高度参照现有照片。纹理外框不是官方有效感应尺寸；碰撞窗口仍为前述假设135×55mm。
- 已修正绘制圆头的端点定义：OpenCV粗线圆头会超出线段端点半个线宽，原先把线段中心端当成完整灯条端点会引入约3—5px渲染偏差。现在分别缩短不同宽度的发光线段，使其完整光照范围落在标注端点，并用投影后的蓝色像素端点边界回归检查。此修正针对仿真，不是修改PnP来迎合错误标注。
- 3号纹理来自现有 `assets/test.png` 中一块装甲板，使用人工检查的端点整平并将红色灯条区域换成蓝色。原始图/纹理SHA与人工端点保存于 `data/fixed-target-input/texture-manifest.json`。它是示例照片合成纹理，不是新采集实车照片，端点仍有约数个原图像素的不确定性。
- 6ms曝光在曝光中点前后各3ms取5个样本积分目标运动；相机姿态在一次曝光内近似保持中点值。另可叠加亮度系数、光学高斯模糊和像素噪声。没有真实曝光响应、滚动快门、自动曝光、灯条频闪或高光材料模型。
- 图像只经过BGR→RGB转换后送给现有YOLO26，使用正式CPU模型和当前6线程、置信阈值、颜色判断、角点精修。初版固定用全画面检测，尚未复刻正式主入口的自适应ROI搜索策略。
- 真值只用于离线匹配与绿色标注，不修补、过滤、替换检测器结果。跟踪器只收到YOLO实际返回的Armor对象；错分为前哨等情况由现有身份/板数检查处理。
- 俯仰、质量、过面门控及300血/50发预算与角点实验共用。固定中心模型只处理四板目标，与正式主入口保持一致。没有改变正式模型、阈值、PID、通信及导航参数。

### 7.2 指标口径

每个非空白场景测双旋向×两个初相位，共4轮。清晰、6ms曝光、6ms曝光叠加亮度0.65/模糊σ0.6px/像素噪声σ2，以及照片3号纹理各一组。空白负对照只运行10s，预期无检测、无发射；它不属于正常任务完成率考核。

召回率仅统计55°内完整入画的板；根据像素中心进行一对一离线匹配，再检查类别、颜色与角点可用标志。大斜角或画外检出只记未匹配，不直接称为误检。另记录四端点RMS及检测耗时P50/P95。所有真值匹配仅用于报告，不参与Tracker关联。

虚拟50FPS、8.36ms帧龄是确定性场景设置；真实检测器壁钟耗时单独计量，没有回写为仿真时钟。渲染耗时属于环境生成成本，不是实车视觉耗时；这些数字不能直接解释为实机全链路FPS。第7.2节四种图像基础场景保持理想弹道/枪口条件；第7.4节另测图像与中等物理误差的联合实验，不能将两类结果简单相乘或等同。
