# 旧帧重放与错误时间戳：恢复时间候选

本轮实现了“只跳过可确认旧帧、保留已有历史”的离线候选。**真正旧帧重放条件下，50发结束时间可由约45.5秒缩到24.5秒；图像留出两种重放条件各少中1／100，且旧实车日志未发现同类元数据异常，暂不启用正式程序。**

恢复耗时和命中数分别报告，未把更快结束等同于命中提高。正式YAML、二进制、PID、通信、导航均未改变，没有启动真实设备。

## 1. 本轮先纠正了一个解释范围

上一轮故障矩阵把新拍摄的图像赋予重复／倒退时间戳：图像内容和相机帧号仍前进。跟踪器拒绝非单调时间，但固定中心、归属和历史视觉残差也收到该时间，会按自己的规则重建。多次异常可使完整50发预算结束时间由约24秒延长到45秒。

这说明时间异常存在恢复代价，**尚不能证明应该保留这些帧的历史**。新图像配错误时钟可能是真正的时钟故障。本轮将它与重送旧图像、旧相机帧号和旧时间戳明确分开，后者才是候选的优化对象。

## 2. 候选条件与实现

新增纯辅助类 `tasks/auto_aim/frame_admission.hpp`，只识别近期见过的精确元数据对。必须同时满足：

- 相机原始帧号非零，当前姿态参考有效，boot／epoch／generation与缓存相同。
- 相机帧号和拍摄时间戳与已见帧完全一致，不根据相似图像或倒退幅度猜测。
- 图像年龄在既有100ms预算内；拒绝重放不会刷新图像寿命。

候选拒绝帧不进入跟踪、固定中心、质量历史或经过计数，也不在该次循环更新命令或发令。缓存最多64项，参考变化、时效失效或主机时间倒退时清除。未知帧号、新帧号配旧时间、相同帧号配新时间、未见过的乱序对和参考变化仍进入普通异常处理路径。

当前只在文件仿真中通过 `controller.reject_verified_replay`显式启用，缺省false。**`standard.cpp`尚未调用此类，正式YAML没有新增运行开关**。不要把这个仿真字段当作实车调参项。

## 3. 真正重放图像的对照

仿真增加有界原始图像／观测包缓存，重放时复制旧内容、旧帧号、旧拍摄时刻，而接收／决策时间继续前进。图像模式把缓存的旧原图再次交给实际YOLO26，不使用真值角点代替检测。评估时的相机投影和世界时刻也对应旧拍摄时刻；求解器仍只获取正式PoseHistory查询后的姿态。

预览标注先克隆图像，避免把评估绿框烧进缓存的旧原图。明确区分曝光时刻与包被送入处理的时刻，拒绝帧没有控制更新或经过提交。

开发组种子151001、初相位21°；独立图像留出151007、53°；均双旋向、50发、60秒射击观察窗。候选判据与条件名单在结果前固定，没有根据命中调整阈值。使用既有假设出膛随机分布和原正式预测时间，不改物理难度。

开发10项包含：无故障、12／20／28秒重放前一帧、重放前三帧、60ms短重放、240ms长重放、新图像重复时间戳、新图像倒退时间戳、重放期间参考切换，以及已获资格后参考变化／图像超龄。每项旧／候选、双旋向共40轮／2,000次发令。

图像留出4项为无故障、旧帧重复、旧帧乱序、新图像重复时间戳，每项旧／候选及双旋向，共16轮／800次发令。图像亮度0.65、曝光6ms、模糊0.6px、噪声2保持一致。合计56轮／2,800次发令；这是恢复策略验证，未声称全场景命中率。

## 4. 结果

### 独立真实YOLO图像留出，每策略每项100发

| 条件 | 旧→候选命中数 | 旧→候选最晚第50次发令 |
| --- | ---: | ---: |
| 无故障 | 95→95 | 24.208→24.208秒 |
| 真正旧帧重复 | 97→96 | 45.488→24.488秒 |
| 真正旧帧乱序 | 97→96 | 45.488→24.488秒 |
| 新图像配重复时间戳 | 97→97 | 45.488→45.488秒 |

旧帧两项每次各减少约21秒，但各少中1发；该组不能证明普遍退步，也不足以宣布命中不受影响。故障改变发射机会和随机误差对应相位，故不能把旧路径多等待后偶然多中1发解释为新模型必然不准，也不能把更早结束包装为命中增益。

关键点开发组：无故障94→94／100；真正重复和乱序各95→94，最晚结束45.628→24.268秒；短重放98→95，31.308→24.428秒。长重放超出时效后仍触发重建，两路径均96／100、31.668秒；参考切换、错误时钟和等待中故障继续生效。没有在开发结果上调阈值让留出更好看。

候选更早结束，一些28秒注入事件已超出该轮实际完成时刻，因此不会发生。没有要求旧／候选经历相同总故障数量来拖长已完成任务；按相同预声明的外部故障时间表和完整50发预算比较，并在审计中核对实际处理的重放事件。

所有56轮发满50发并完成300血；700条无故障／新图像时钟异常／等待故障控制记录逐字段一致（<1e−9）。旧候选图像逐轮命中非退步条件未通过，部署标记为false。

## 5. 实车历史证据筛查

只读检查252份 `logs/diagnostics/vision-*.jsonl`：可解析778,394条，其中778,364条具有非零相机帧号和有效时间。文件内、可用参考字段范围内，帧号＋时间完全重复为0，记录时间非单调为0，相同帧号但不同时间为0。另13条JSON损坏行排除，未修改原日志或猜测损坏原因。

这是现有**抽样诊断记录**，未记录的相机帧、旧格式缺少完整身份字段、丢失／损坏记录均是盲区；不能据此保证相机从未重放。其结果说明，目前缺少把旧帧重放认定为现场问题原因的证据。不能将仿真的21秒收益直接宣传成实车收益。

每份源文件指纹和行数保存在 `logs/frame-admission-audit.json` 的 `recorded_metadata` 中，没有复制或覆盖原始实拍资料。

结果清单 `logs/frame-admission-development.json`、`logs/frame-admission-holdout.json`，完整审计 `logs/frame-admission-audit.json`。源码和离线二进制指纹保留在本轮清单中；此前实验的生成指纹不改写。

## 7. 部署决策与后续优先级

保留辅助类和离线实验，不接入正式循环。除了图像留出未满足命中非退步，真实循环还需要验证跳过帧时的串口心跳、最后有效控制保持、模式切换和任务租约。本轮模拟的“无新命令”尚不等于完整UART／MCU行为通过，不能直接在实车主循环加一个 `continue`。

正式YAML SHA256仍为 `e087e02c2c6ad257acef5a0808950a42f15445c4ed00714807023dad7427fd90`，正式二进制仍为 `dbc3d740d18255383af4f211b9bb8b740bbee0c65d31b0d18c8a757f378d5cfe`；端点候选仍false，其他实车参数不变。

这条分支降低优先级，后续先推进端点算法的正交拆分和已有实拍的几何／光度验证。若现场出现可配对的原始帧号与时间重放证据，再补完整通信／模式行为及更多独立条件，评估是否接入。新图像的错误时间戳仍需真正校核时间来源，不能靠本候选隐藏。
