当前正式配置为水平弹着修正 -1.95°、相位 410 ms、每隔两面请求一次。已撤回之后的逐发方向补偿及 350 ms 独立定频试验，对应源码、构建目标和配置项均已移除。相位误差超过 22.5° 后校准卡住的修复、周期校准、串口互斥和有效性保护保留。

这次为选择性回退，不是用旧 Git 提交覆盖全部工程。PID、摩擦轮参数、相机标定与俯仰修正不变。详细边界见 `docs/vision_policy_rollback.md`。

2026-10-25。适用于当前 Sentinel、四块等间隔装甲、固定中心且匀速旋转的测试。

正式参数只有 `configs/standard.yaml`，修改后重启原自瞄入口生效；不要改启动器生成的 runtime YAML。

```yaml
sentinel_fire_min_interval_ms: 200
xuc_periodic_fire_enabled: true
xuc_periodic_phase_offset_ms: 410
xuc_periodic_every_n_faces: 2
xuc_event_fixed_omega_rad_s: 4.56
xuc_direct_yaw_impact_correction_deg: -1.95
```

- `xuc_periodic_phase_offset_ms`：以视觉观测到装甲正对靶车中心的时刻为基准，晚多少毫秒请求拨一格。增加表示发令更晚，减小表示更早；按当前估计的一个装甲经过周期取模，支持负值，范围为 ±2000 ms。这次保留用户调好的 410 ms，不代表已测出膛延迟。
- `xuc_periodic_every_n_faces`：1 为每块经过时请求一发，2 为隔一块请求一发。允许 1–16。请求间隔为 N 倍估计的单面周期；当前 N=2，名义间隔约 688.946 ms，之后随视觉校准做小幅调整。
- `xuc_event_fixed_omega_rad_s`：启动时使用的角速度绝对值，单位 rad/s；当前仍为 4.56。方向由视觉提供，稳定过中心观测取得锁定后，实际发令周期逐步跟随观测结果，不把设定值再次当作独立测速值混入估计。
- `sentinel_fire_min_interval_ms`：传输层防重复下限，保留 200 ms。它不定义节拍，不要写 0。节拍至少须比该值长 5 ms，否则启动检查拒绝配置。
- `xuc_periodic_fire_enabled: false`：恢复原相位窗口策略。若需要恢复旧一秒限频，另外把 `sentinel_fire_min_interval_ms` 改回 1000。

固定节拍模式下，`xuc_event_fire_delay_s: 0.640`、其 min/max 和弹速不决定发令节拍；旧延迟只用于诊断画面的假定命中时间。弹速仍参与俯仰弹道补偿，不要随意修改。NEXT/SHOT 板号仍是模型归因，不能证明弹丸出膛和实体命中。

## 行为与验证边界

视觉先接受新鲜、可信的正前方装甲观测，按图像对应时刻建立初始节拍；随后利用有迟滞防重复的过中心观测和窗口中位数滤波缓慢校准周期及相位。首次相位已错过则等待下一周期；时隙迟到时跳过，不积压、不补发。

每次请求仍受 AUTO、姿态、当前真实观测、云台对准和下位机发射许可限制。短暂换板或关联拒绝保留时钟（沿用 `xuc_rotation_tracker_dropout_hold_ms: 250`），但无新鲜观测的当前时隙禁止发令；超过保留时间、目标身份/模型重建、姿态不可用或退出 AUTO 清除节拍，恢复后重新观察中心建立节拍。不会在失去观测后持续盲发。

发送相位按当前校准的时钟复核，避免再用有噪声的逐帧视觉相位否决同一个时隙。最新视觉相位与时钟的剩余差异记录为 `periodic_visual_phase_error_deg`，不伪装成已测出膛相位。单帧抖动或单次异常过中心不直接重设时钟；可靠观测暂时不足时保持最近的周期估计。

这是逐次请求拨一格，未改为拨弹盘无条件连续转动。未改电控固件、拨弹 PID、摩擦轮转速或通信协议。保护拒绝、错过时隙和机械跟不上均可能使实际间隔更长；实际发弹数及命中率需要现场验证。

2026-10-24 的历史验证记录为：正式主程序编译、独立节拍测试、当时的 4 项 CTest 以及不打开设备的配置检查通过。测试覆盖旋转双方向、固定周期、相位偏移、隔板请求、漏时隙、旧图像及非法配置。构建日志见 `logs/periodic-fire-build.log`，测试见 `logs/periodic-fire-tests.log`，生效配置见 `logs/periodic-fire-config-check.json`。测试夹具补齐既有 `nav_turn_rpm` 成员以适配实际 `RC::OnPC`；生产固件没有改动。2026-10-25 本次验证范围见文末，不能沿用历史 CTest 数量作为本次结果。

现场只调相位时，保持机器人位置、靶车转速和摩擦轮状态一致。整组稳定偏移先查相位；命中随时间逐渐漂移先查周期。若机械供弹不能稳定跟上，先设 `xuc_periodic_every_n_faces: 2`，不要用更大的请求频率追赶。

## 2026-10-25 累积失步修复

用户保持 `-1.95°` 水平修正、`410 ms` 相位、每隔两面发一次。`vision-1792863516042422.jsonl` 中 51 次发令期间，上位机 yaw 积分输出为零，而视觉相位相对固定时钟持续增长。相位趋势支持“观测节拍与设定节拍失配”；它不是独立测速或靶车机械转速波动的证据。

原 `FixedCadenceTrigger` 只同步起点，之后不再校正。本次仍保留该接口及原有保护，内部增加独立过中心时钟：至少收集八个过中心事件后才用于校准，最近最多保留 24 个事件。只取至少相隔四次经过的事件对计算周期，再对这些周期取中位数；避免真实日志中相邻过中心“一长一短”的抖动带偏频率。不将固定 4.56 rad/s 作为独立观测加权回去。

- 周期只能在设定单面周期的 ±10% 范围内校准；每次可靠更新的周期变化不超过 0.5%。
- 每次可靠更新的相位平移不超过 3 ms，按最近过中心时刻调整，避免长时间运行后小周期变化乘上整个历史时长导致跳变。
- 用户配置的水平修正、410 ms、隔两面、弹速、延迟及门槛都没有被本次修改。410 ms 仍按单面周期取模，语义与原实现一致。
- 过中心滤波未锁定或暂时拒绝异常观测时，不反复重启发射时钟；原有长丢失／姿态无效／退出 AUTO 重置机制保留。
- 新增诊断 `periodic_command_interval_ms`、`periodic_clock_calibration_updates`、`periodic_clock_phase_adjustment_ms`。`PERIODIC_FIRE` 记录当前估计间隔，不再始终打印设定速度换算的名义间隔。

离线测试覆盖 4.56 设定值与恒定 4.50 实际值的偏差、双方向、隔一面／隔两面、短丢帧、异常相位、长丢失及六分钟连续运行。测试中的校准后相位误差是理想合成观测下的算法结果，不是实机命中率；相机外参、视觉相位本身的系统误差和实际出膛延迟仍需现场验证。

本次实际验证：`standard` 和 `gyro_phase_scheduler_test` 编译通过；独立节拍测试通过；`tools/field_start_autoaim.sh --check` 预检通过且不打开设备。当前根 `build/` 未注册 CTest，`ctest` 返回“No tests were found”，不将其计为已执行测试。报告分别在 `logs/periodic-fire-calibration-build-result.json`、`logs/periodic-fire-calibration-checks.json` 和 `logs/periodic-fire-calibration-tests.log`。

另外对上述真实诊断 JSONL 的模型相位和资格条件做离线回放，采用固定 25 ms 处理年龄近似，未复现原每次串口发送时刻。1475 条合格观测、约 40.4 秒区间内发生 90 次校准；最后十秒的相位绝对误差中位数由原时钟的 26.36° 降到 5.62°。结果见 `logs/periodic-fire-calibration-replay.json`，不代表实测出膛或命中误差。配置文件逐字节校验保持不变；没有启动主程序、相机、串口控制或发射。

## 大残差恢复检查
