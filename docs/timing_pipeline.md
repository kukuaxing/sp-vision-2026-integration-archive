# 图像／姿态时序链故障注入

本轮补上旋转靶仿真此前没有经过的真实 `PoseHistory` 查询与发令前复查。在预先固定的诊断矩阵中，**超龄／未来图像、姿态断流、重复／乱序观测及等待期间参考切换均未造成无效发令；固定传感延迟仍可能通过时效检查。** 未发现本轮能够确认并需要修改的正式代码缺陷，没有部署新控制策略。

这是实际几何、跟踪、预测和时序辅助模块的组合测试，包含真实YOLO图像子集；**不是完整 `standard.cpp`、UART、MCU或实车断电测试**。没有启动真实控制程序，未修改正式配置、PID、通信或导航。

## 1. 正式路径与原仿真的差别

正式Sentinel路径在图像推理后调用 `pose_at_capture(t)`，获取图像时刻的姿态；缺少插值括号、姿态过旧或参考不匹配时，清空该帧观测。真正发令前再次检查姿态参考、跟随误差和图像年龄。姿态查询不允许用最新样本代替缺失的拍摄时刻样本。

原文件仿真直接把虚拟拍摄时刻姿态交给Solver，缺少上述到达时间、插值括号和发令前参考变化的组合。因此本轮增加显式 `timing_pipeline` 仿真选项；缺省不启用，原实验路径保持兼容。

新增模块每5ms按虚拟物理姿态生成一条IMU观测，保存32位设备时间、序号、参考身份和独立到达时刻。只有已经到达的包能进入正式 `PoseHistory`；Solver只接收查询后的估计姿态。传感器内部处理延迟和串口输送延迟分开建模。真实姿态用于生成观测及评估，不作为估计失败时的回退。

参考变化先发生在虚拟设备端，**主机仅在新参考包实际到达后得知**；旧会话迟到包在主机已见新会话后被丢弃。初步实现检查时补齐了这一因果约束，并以最终实现重跑矩阵。独立单元测试覆盖新会话迟到50ms期间主机不能提前更新参考身份。

## 2. 固定诊断矩阵

共同条件：种子141001、初始相位13°、双旋向±4.56rad/s、50Hz严格采样时钟、60秒射击观察窗、300血／50发完整预算。忙时明确丢弃新采集帧，不把采集时间向后推。关键点组使用假设0.25px噪声；仿真出膛均值340ms、标准差25ms、弹速／角散布和有限伺服均为明确假设。预测器保持正式330ms及已有视觉历史校正，没有调参选择最佳结果。

关键点模式18项，每项双旋向，共36轮／1,800次发令：

| 项目 | 注入方式 |
| --- | --- |
| 基线 | 启用时序链，不额外加故障 |
| 图像延迟 | 12—14秒增加40ms或120ms |
| 时间戳偏差 | 同窗口向未来40ms或向过去80ms |
| 重复／乱序 | 12、20、28秒各注入一帧相同时间戳或回退60ms |
| 图像短缺 | 12秒起缺失80ms |
| IMU断流／冻结时钟 | 12秒起220ms，不到包或源时钟不再前进 |
| 运输延迟突发 | 12秒起300ms窗口增加70ms到达延迟 |
| 等待中参考变化 | 40ms等待与一次设备参考变化相交 |
| 等待中图像变旧 | 固定窗口增加120ms等待 |
| 内部传感延迟 | 整轮姿态值落后30ms、设备包时间仍正常前进 |
| 恒定运输延迟 | 整轮每包延迟25ms到达 |
| 组合故障 | 图像延迟＋IMU冻结＋参考变化 |
| 已合格后参考切换 | 12—14秒首次原门槛全部成立时，切换参考并等待40ms |
| 已合格后图像超龄 | 相同因果触发条件下等待120ms |

后两项只读取当时控制器已有资格，不看命中或未来真值。前面的固定时刻故障可能发生在原门槛已关闭时，不能只据“没有发令”证明最后一道复查有效；这两项用于保证真正覆盖该情况。

实际YOLO26／原端点图像子集复核基线、图像120ms延迟、已合格后参考变化、已合格后图像超龄、向过去80ms时间戳共5项，双旋向10轮／500次发令。图像亮度0.65、曝光6ms、5次对称采样、模糊0.6px、传感噪声2；没有真值检测回退。总计46轮／2,300次发令。

## 3. 观察结果

| 检查 | 本轮结果 |
| --- | --- |
| 无效拍摄姿态／参考不匹配时发令 | 0 |
| 非单调观测的关键检查 | 16帧均无新测量更新、无发令 |
| 参考切换后的旧补偿 | 8次重建时历史周期和修正量均清空 |
| 已合格后再发生故障 | 8次请求均被最终复查拦截 |
| 重复经过机会 | 同模型上下文计数与独立世界物理面经过检查均未发现重复 |
| 全部预算和任务 | 46／46轮均发满50发，均完成300血目标 |
| 最晚第50次发令 | 45.30836秒，仍在60秒观察窗内 |

实际图像基线为88／100；120ms图像延迟组89／100，合格后参考切换88／100，合格后图像超龄88／100，过去80ms时间戳组87／100。它们是同一诊断种子不同故障下的结果，**不是新控制器的性能增益或独立命中率验证**。故障会改变发射机会与随机误差落到的相位，不能由某组多中1发推出延迟有益。所有轮次最差43／50也不能替代更多种子和实车验收。

重复／乱序观测能显著延后完成：关键点基线第50发约24秒，三次异常组最晚45.308秒。这里没有观察到违规重复发令，但应继续研究质量历史重新积累的代价；不能简单屏蔽所有时间异常来保留历史，因为真正时钟或坐标参考改变必须重建。

“同一次经过”的内部计数在模型重建后可能重新编号，因此审计在参考／跟踪／残差模型上下文内比较，不把不同模型中同名整数误报为重复；另外独立用世界几何求交面和完整转数检查真实物理面经过，避免仅依赖内部编号。

## 4. 仍然无法由时效检查排除的延迟

`PoseHistory`使用到达时钟估计设备到主机的时间映射。**顺序正确、包持续到达、插值成功，不代表姿态对应真实曝光时刻。**

独立动态姿态单元测试设定Yaw速度0.3rad/s：

- 30ms传感器内部延迟、包时间正常前进时，姿态查询仍可能有效，但相对真实姿态落后约0.009rad（0.516°）。
- 恒定25ms运输延迟可能被吸收到到达时钟偏移中，查询仍有效，测试姿态落后约0.0075rad（0.430°）。

这些是人为动态姿态条件，不是实际测到的硬件延迟或实车角误差。静态中心跟随时，云台长期接近不动，闭环分数也可能几乎不变，不能据此排除延迟问题。正式结构已将 `sensor_latency_known`、`synchronized`及假设运输预算明确区分；本轮没有把30ms预算包装成硬件同步认证。

下一步实物测量应分别约束相机曝光时间、IMU采样／内部处理时间、包到达时间与发令／出膛时间；不能直接把本轮30ms或25ms写进实车配置。
