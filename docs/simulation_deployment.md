# 仿真经验向正式视觉程序的部署

部署结论：正式程序包含新诊断与可切换端点候选，`corner_refine_brightness_invariant_subpixel: false` 保留旧端点路径。新算法显著改善模拟测距，但未通过预先约定的命中数/最差轮不退步门槛，未默认启用。

## 改动范围

唯一正式工程 `/home/rcsdart/rm27`，本地同步目录 `sp-vision-2026-integration-archive`。沿用原 `build/standard`、启动入口和 `configs/standard.yaml`，不创建另一份程序/配置分支。本轮只处理视觉软件、诊断和离线验证，不启动动作、发射或导航任务，不烧录或更改PID。

## 已有能力核对

正式主入口已含短缺帧的同目标上下文保留（最长150ms，缺帧当帧仍无开火资格）、成熟同面历史视觉残差校正、固定中心模型归属、同面去重、连续帧/俯仰/历史预测质量/新鲜姿态门控。这些仿真相关修复已在正式源码，不重复叠加另一套控制分支。

正式CW/CCW延迟仍各0.330s，用户已有瞄准、落点与发令参数不因仿真标定自动重写。仿真0/+20ms综合时序标定、未通过留出的-0.12°、小半径选面和真值影子模型均不进入实车控制；不会用减17cm或固定增加2px掩盖几何问题。

## 新端点算法

`AdaptiveCornerRefiner` 新增 `brightness_invariant_subpixel`，由唯一正式配置的 `corner_refine_brightness_invariant_subpixel` 控制，缺省false兼容旧配置。

开启时使用局部Otsu阈值，移除原 `0.65*Otsu+0.35*固定阈值` 对亮度的固定偏置；保持同一轮廓/拟合轴，沿轴追踪该等强度边界，用双线性采样及线性插值得到亚像素端点。追踪步长0.25px、搜索界限4px只是有界边界搜索，**不代表固定伸长量**；找不到边界或ROI被截断时拒绝该候选，不补猜测端点。

保留原来的轮廓长宽比、填充、左右长度/方向一致性、ROI位移、颜色、位姿和开火门槛。没有调低置信度或放宽射击角度。

八项同条件几何对照的中心X平均误差：

| 条件 | 旧算法 | 新算法 |
| --- | ---: | ---: |
| 理想角点 | 约0 | 约0 |
| 清晰，仅精修 | +6.00cm | +1.87cm |
| 仅降亮度 | +10.84cm | +1.47cm |
| 仅曝光 | +8.36cm | +1.75cm |
| 仅模糊 | +7.24cm | +1.52cm |
| 组合退化，仅精修 | +14.38cm | +2.37cm |
| 清晰，实际YOLO | +10.30cm | +2.85cm |
| 组合退化，实际YOLO | **+16.85cm** | **+2.77cm** |

退化实际YOLO的灯条长度比约0.9210→0.9888，55°内有效位姿494→493条；保留这一次无效位姿，没有用真值补齐。算法不读取真实端点、距离、转速或命中。几何夹具本身属于开发/诊断，不能把这张表叫实车精度。

亚像素等强度边界仍可能与实物56mm对应的发光边界不同，剩余约2.77cm偏差未消失；还需真实已知位置/曝光数据检验。已有经验落点修正可能包含旧几何偏差，实车须重新核对，不能凭仿真直接替换它们。

## 留出协议与复现

候选预先固定为Otsu＋亚像素边界这一项，不扫描阈值挑最优。图像新留出种子6011/7001/8011、初相位15°/60°，双旋向，每候选12轮600发，仍为300血、50发预算；实际CPU YOLO、噪声、曝光、伺服、弹速和出膛随机扰动条件保持。

本轮用于比较端点的发射基准沿用前轮实验的分旋向0/+20ms，两候选相同；这些附加时间只在仿真控制器中，正式程序不部署它们。这不是完整standard/串口/电控的运行重现。成对验证逐发随机弹速和出膛抖动一致、同种子/旋向/相位、均发满50预算，不向控制器反馈理想HP。

cmake --build build/native-offline -j2 --target fixed_target_geometry_probe fixed_target_image_sim

生成 `logs/endpoint-deployment-geometry.json` 与 `logs/endpoint-deployment-images.json`。完整源数据、候选配置SHA与源码/权重/二进制指纹随结果保存；阶段性结果不算验证完成。旧几何/命中率报告保留生成时的源码与正式配置指纹，不冒充本轮重跑。

为排查旧分旋向标定的影响，额外用正式时间设置（无0/+20ms附加项，应用正式已有视觉残差）做新种子12007、40°、双旋向的小规模检查：旧端点91/100，新端点87/100，最差90%→86%，均2/2完成。该组也未支持采用新端点；不能把退步全部归咎于旧+20ms标定。这是200发文件仿真检查，仍未运行完整standard/真实电控。

因此本轮只部署经过验证的修复、诊断与候选切换能力；候选保持关闭，不利用本轮最终数据继续挑阈值或补偿，再冒充独立验证。后续需要在另一组开发数据中分离几何、伺服跟随和开火时机的影响，再用新留出组评估。

按同种子、旋向、初相位和发射序号配对，542发两者均中、35发均未中、14发旧中变新未中、9发旧未中变新中。不是全部落点统一移好/移坏的现象；当前门槛依据该组实测退步拒绝默认启用，不声称已证明普遍的统计劣势。

## 启动方式

部署后由用户按原入口启动；启动器每次从唯一正式YAML生成运行缓存，会原样传递新开关。已经运行的进程不会热更新。此次不重启服务或启动机器人测试。

需要回到原端点路径时，将 `corner_refine_brightness_invariant_subpixel` 设为false，再由用户重启视觉进程；不需要回退固件或修改PID。
