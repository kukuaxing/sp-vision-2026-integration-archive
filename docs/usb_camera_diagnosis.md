## 判断与边界

目前没有找到可确认修复的软件设置。证据更集中于 USB 3.0 连接建立阶段，仍无法区分相机端高速接口、接触/供电、主机特定端口或双方兼容性。相机 USB 2.0 能成像不证明其 USB 3.0 电路正常；集线器成功连接也不证明相机供电条件正常。

如需继续定位，最有价值的是同一物理口接已知正常 USB 3.0 设备并确认 5000M，以及相机接另一套独立系统的已知正常 USB 3.0 口。尚未完成这两项完整对照。

## 公开案例核对（2026-10-05）

未找到 MV-CS016-10UC 与本机组合的明确已知故障或确定修复。主机 DMI 的整机和主板型号均为 Default string，目前只能确认 i7-1280P、8086:51ed；AMI 5.27 不能代替整机型号。以下案例按适用范围区分：

- [英飞凌官方枚举排查指南 Q3](https://community.infineon.com/t5/Knowledge-Base-Articles/Trouble-Shooting-Guide-for-the-FX3-FX3S-CX3-Enumeration/ta-p/248415)：同时检查线材、时钟、供电噪声、硬件布线和设备固件的 SuperSpeed/LPM 设置。指南面向设备开发者；不能把其固件 API 操作直接套用到封闭海康固件，也不能将主机根集线器的临时唤醒视为设备侧 LPM 已排除。
- [同型号海康开源封装的故障说明](https://github.com/Alliance-Algorithm/ros2-hikcamera#故障排除)：其 udev 方案针对 lsusb 可见、SDK 不可见。我们 USB 3.0 故障时连 lsusb 都不可见，已有海康权限规则，因此此方案不匹配当前现象。

- [研华 Alder Lake 公告](https://advdownload.advantech.com/productfile/Downloadfile3/1-332W435/USB%202.0%20device%20enumeration%20issue%20on%20Alder%20Lake%20platform_v1.0.pdf)：描述特定线缆传播延迟下 USB 2.0 Full-speed 设备枚举失败，并建议外接集线器等措施。当前相机是 USB 2.0 能取图、USB 3.0 无法建立连接；不能据此判定命中了该缺陷。

下一项有区分价值的实验是借用已知正常 USB 3.0 集线器，连接“小电脑 USB 3.0 → 集线器 → 相机”，检查相机本身是否以 5000M 枚举，再做连续采集。只看到集线器为 SuperSpeed 不足以确认相机为 SuperSpeed。若带独立供电的集线器使相机恢复，仍需区分供电改善与信号路径/兼容性变化，不能直接断言电流不足。该实验尚未完成。

## 00:50–00:58 CH340 换 USB 3.0 插座后的定位

用户将 CH340 换到 USB 3.0 物理插座。系统显示它从 USB 1-6 移至 USB 1-2，仍为 Full-speed 12M，与相机 USB 1-5/480M 同属 Bus 001；USB 3.0 根总线 Bus 002 仍没有子设备。因此这次换口没有把 CH340 移到独立的 SuperSpeed 总线上。

## 固件源码对遥测有效位的解释

核对实际版本 2026100402 的 `RCS_code_rmv/STM32F405` 源码后，需补充上述健康报告的解释：

- 两台 IMU 的串口接收和解析任务在初始化后自动运行，不需要视觉发送运动指令；但 RMV 遥测只在 HELLO 会话建立并维持心跳后发送。
- 小 Y 原始姿态会在收到有效 HI91 数据后自动上报。解析器同时检查整帧 CRC 和四元数范数，不会只凭串口有字节就标记姿态有效。
- 大 Y 的四元数无效不是本次证据能证明的 IMU 输出故障。`rmv_board_config.h` 中 `big_imu_world_aligned=false`，`xuc.cpp` 明确清除四元数有效位并将四元数清零；角速度和加速度继续上报。这是未确认两 IMU 坐标对齐时的主动屏蔽，不会因重启自动解除。当前大 Y 来源能持续通过严格 HI91 解析，也说明 MCU 实际接收到了带有效四元数的原始帧。
- 相机支架 `sensor_id=0` 的能力位受安装确认、IMU 是否随 P 运动及 geometry_revision 控制。当前相关确认值为 false、版本为 0，因此此来源未启用，不是上电后丢失的一路数据。
- P/大 Y 关节状态来自达妙 CAN 实际反馈；仅主控上电不保证电机驱动上电、ID/模式正确或主动产生反馈。当前无使能请求时发送函数不持续查询反馈，控制模式也会影响驱动是否回报，不能仅凭反馈超时判定 CAN 接线坏。上报在线要求近 100 ms 内收到有效反馈且无驱动故障。

这些解释只记录现状，未修改固件确认标志、安装参数或电机使能状态。
